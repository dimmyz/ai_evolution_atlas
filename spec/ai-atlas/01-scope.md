# 01 — Scope and release boundary

## Sprint 1 / v0.1 scope

### Historical boundary
Primary narrative window: **2017 through 2026**.

The entry anchor is the Transformer era. Earlier history may appear only as concise prerequisites or “before 2017” context chips.

### Content target
Ship a curated dataset of roughly:
- 30–40 milestones;
- 15–25 model/system entities;
- 8–15 organizations/labs;
- 8–15 people where genuinely useful;
- 10–20 papers/technical concepts;
- 40–70 typed relationships.

Counts are targets, not reasons to invent weak entries.

### Required product surfaces
1. Hero / orientation area.
2. Interactive chronological timeline.
3. Detail drawer/panel for a selected milestone/entity.
4. Lineage/relationship graph for a meaningful subset.
5. Filter by type / organization / era.
6. Search or quick-find.
7. Visible citations/source links.
8. Responsive desktop + usable mobile fallback.
9. Shareable selected-item state if inexpensive (URL hash/query); otherwise SHOULD.

## Editorial eras

The UI may use high-level editorial bands such as:
- Transformer foundations;
- scaling + instruction/chat;
- open foundation models + multimodality;
- reasoning + agents/tool use.

These bands are **editorial navigation**, not objective scientific periodization. Label accordingly.

## Primary language

Sprint 1 default: **English** UI/content for canonical AI terminology and broader reuse.
Russian localization is Phase 2 unless the human changes this before kickoff.
Data structures should not make later localization unnecessarily difficult.

## Out of scope for Sprint 1

- authentication/accounts;
- CMS/admin backend;
- live automatic model/news ingestion;
- user comments;
- model benchmarking dashboards;
- 1950–2016 full historical coverage;
- automatic graph inference from embeddings/LLM guesses;
- production analytics/ads;
- paid images or scraped copyrighted graphics;
- brand-logo wall as a design substitute;
- large-scale database/backend deployment.
